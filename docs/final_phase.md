# 最終フェーズ: 全域生成と「見回して詳細」の反復記録

方針: 地面視点(目線1.65m)と空中視点を自動選定してレンダ → 不足を列挙 → 汎用モジュール(複数パターン使い回し)を作り手続き配置 → 再レンダ。LoDは行わない。
画像は `out/render/final/` に出す(gitignore、コミットしない)。

## パイプライン
- `scripts/build_city.py --region odaiba|west --mode osm|infill|hybrid [--render] [--per N]`
- `src/vt/city.py`: 領域(中心±half[m])を一括生成 → タイル(既定450m)に面/インスタンスを重心で振り分け。継ぎ目や二重化が出ない。
- `src/vt/blocks.py`: 道路(車道+歩道)・緑地・水域・線路/高架・護岸・駅・(hybridでは)OSM建物を除いた空き地を **街区** にし、ロットへ再分割 → 建物フットプリント/高さ/用途を割当。街区の道路密度と領域中心からの距離でゾーン(core/urban/mid/low/industrial)を決め、高さは中心ほど高い。小ロットは小物建物、一部は駐車場(白線区画+駐車車両)。
- `src/vt/city_props.py`: 走行車両(車線ごと・左側通行)、路肩の平行駐車、歩行者(歩道・横断待ち・公園)、自転車、高架上の車両。
- `src/vt/modules/lib_city.py`: 乗用車(5車種×7色)/タクシー/トラック/バス/二輪/自転車、歩行者(低ポリ)。
- USD: タイルごとに `out/usd/city_t{i}_{j}_*.usdc`(地面/道路/線路は材質別Mesh、建物/ファニチャ/植栽/小物は PointInstancer)を書き、`city_all.usda` で束ねる。レンダはカメラ周辺タイルだけを読み込む。

## ラウンド1(基準: OSM建物のみ・小物なし, お台場 1.8km角)
見つけた不足:
1. 建物が圧倒的に少ない。広い舗装(plaza)が何もない白い平面として広がる/空中視点でスカスカ。
2. 道路に車が一台もない/歩行者がいない(生活感ゼロ)。
3. 検証カメラが建物の内側に入って真っ黒になる(視点選定のバグ)。
対応: 街区→ロット→建物の自動配置(blocks.py)、車両/人モジュール+配置(lib_city/city_props)、視点選定で建物内を除外。

## ラウンド2(西側=田町〜芝浦〜品川の本土側、hybrid、中心±700m)
結果: 道路の左右に建物が連なり、走行車/歩行者/バス/ガードパイプが見える(街区1413ロット→建物1352+小物298+駐車場54、OSM建物と合わせ計2542棟)。
見つけた不足・不具合:
1. レンダの重さ: 個別オブジェクト約60万個でメモリ8GB・1枚数十分 → Geometry Nodes のインスタンス化(`render.add_instances_gn`)へ変更し、ground 15〜20秒/枚、空中 25〜35秒/枚に。
2. 高層ビルの一面が無窓の白い壁になる(`blank` 辺が高層にも適用) → 高層(9階以上)では無窓辺を作らない。
3. 屋上が平らなグレーで単調(空中視点) → 屋上設備の数を約2倍に。
4. 水平線に濃い帯(水面が有限) → 水面を80km角に。
5. 歩行者がカメラ位置に重なって視界を塞ぐ → レンダ時にカメラ6m以内のインスタンスを除外。
6. 車線の中央分離帯の上にカメラが載る → 車線上に配置。
7. 車の質感が暗く、窓が不透明な黒(要ラウンド3で確認)。

## ラウンド3(お台場 1.8km角 hybrid と 西側 再レンダ、地面+空中 各13〜19枚)
お台場: 道路沿いに建物が連なり、公園・水辺・運河は開けたまま。空中視点でもスカスカな所は無くなった(OSM建物185棟+自動1074棟)。
見つけた不足・不具合:
1. 谷間の道・歩道が暗く潰れる → 地面視点の露出を上げる(−2.9→−2.2)。
2. 車がのっぺり(ホイールアーチ/ドア合わせ目/ハンドルが無い、窓が黒い) → アーチ・ドア線・ハンドル追加、ガラスを反射的な材質に。
3. 住宅街の道に電柱/電線が無い(東京らしくない) → 生活道路の片側に電柱(約35m)+3線+通信線のカテナリを自動配置(`city_props.utility_lines`)。
4. 公園が芝だけでベンチ・遊具が無い → 面積に応じてベンチ+ゴミ箱、遊具(滑り台/ブランコ/砂場)、パーゴラ(`park_amenities`、新規モジュール5)。
5. 地上線路の脇にフェンスが無い → 緑のメッシュフェンスを両側に(`rail_fences`、`fence_mesh_2m`)。
6. 歩行者がまばら → 歩道の歩行者密度を約2倍。
7. (未解決/許容) 高架下の視点で右端が黒く抜ける、車線上の視点では前方の車が視界を塞ぐ。

## ラウンド4(西側 hybrid 中心±700m、USD出力込み、地面12+空中7枚)
結果: 総props 28088(電柱/フェンス/ベンチ/遊具/船/車/人)、建物2542棟(自動1352+OSM)、USD 16タイル/107レイヤ(約234MB)、総2.6分(ベース3分キャッシュ後)+レンダ。生成 625s(キャッシュ無し初回)。
残課題: 高架下視点の黒抜け(高架桁と壁の境界)、車がローポリで質感が単調、ボートは水際のみで運河内は未配置、高密度化で建物の歩道側が暗く潰れる(露出は固定)。
pytest 44件通過。`scripts/gn_check.py` は GN インスタンスの動作確認用(テスト対象外)。

## 小領域スポット反復(`build_city.py --spot NAME [--round N]`、half=200、保存先 `out/render/spots/<spot>/round<N>/`)
プリセット: `odaiba_intersection` / `west_intersection` / `west_highrise` / `yurikamome`(台場駅) / `shuto`(首都高1号羽田線・台場線の高架下) / `rainbow`(芝浦側取り付け) / `rainbow_pier`(橋脚・主塔) 。任意地点は `--center lon,lat --half 200`。生成は1地点あたり約15秒、レンダは1枚10〜25秒。
画像: 各 round の `sheet_0.jpg` が一覧。ラウンド1→2→3→4/5 の比較は同じファイル名で並べられる。

| round | 内容 |
|---|---|
| 1 | 修正前(ただし新しい車のメッシュ平滑化は先に入っている)。rainbow は座標が水上でクラッシュのため欠番 |
| 2 | 露出/Look 変更、人モデル刷新、(rainbow 初回) |
| 3 | 空中視点の高度を最高層の上に、視点を建物から3m以上離す、バスのモデル刷新、バンパー/グリル、座標プリセット見直し |
| 4 | 高架下/駅前の視点選定を作り直し、露出 −1.8 |
| 5 | 真っ黒/暗すぎるカットを視点をずらして自動再撮影(`render_view_checked`) |

見つけた問題と対応:
1. **車がローポリ**(6角断面で折れ線): 断面を10角形(面取り・Aピラー傾斜・肩)にし、断面列を Catmull-Rom で3分割補間。塗装を艶あり(粗さ0.15〜0.2, 金属0.6)にして汚れテクスチャを外し、窓ガラスを反射寄りに。前後バンパー・グリル・ドアハンドル・ホイールアーチを追加。バスも同じ機構で作り直し(窓帯・腰の白帯・行先表示)。
2. **谷間・高架下の暗さ**: AgX "Medium High Contrast" をやめ "Base Contrast"、露出 −2.9→−1.8、空光を2倍。高架下の道路も形が見えるように。
3. **高架下の黒抜け**: 原因は視点が橋脚/桁の中に入っていたこと(全面真っ黒)。視点が暗すぎ(平均輝度<22)なら±5〜9m ずらして再撮影し最良を採用。高架下視点の選定も桁沿いの横オフセットで確実に拾うようにした。
4. **人が箱の寄せ集め**: 楕円断面の胴/腕/脚、膝の曲がり、卵形の頭+髪、靴に。歩行者の身長は決定論に(以前は `hash(str)` で実行ごとに変わる不具合があった)。
5. **カメラ近傍の車/人に視界を塞がれる**: 距離条件が二乗値と混同されていた(2.4m→6m)。
6. **空中視点が建物に埋まる**: 高度を周辺の最高層+25mに。
7. **選点のバグ**: 公園/水辺選定の `rng.sample` が母数不足でクラッシュ、水域のみの領域で空リングを参照。
8. **座標**: 台場駅・芝浦・レインボーブリッジ(東京港連絡橋の線上)を OSM から探索する `scripts/probe_spots.py` を追加して実座標を使用。

残課題:
- 水面が鏡のように反射し、水際/水上の地面視点で水平線が白く飛ぶ(レインボー橋脚の地面視点)。
- ゆりかもめ台場駅の駅前視点は暗い壁(1階の無窓壁のシャッター)に面しがち。駅舎そのものを見せる視点選定が未実装。
- 生垣モジュールが立方体状で目立つ(vegetation 側)。
- 車は中距離なら十分だが、至近距離ではまだ面が見える。トラックのキャブは未改良。
